# Files and functions

All paths below are relative to `urc_state_machine`. Start with the
[system overview](../README.md). This guide uses the actual function names;
proposed names from discussions have not been applied.

## The objects and values

| Name | Meaning |
| --- | --- |
| `NavCoordinator` | The ROS node that owns the mission and connects all the pieces. |
| `mission_` / `ActiveMission` | Current mission kind, state, waypoint, marker, navigation goal, retry count, and deadlines. |
| `navigation_` / `NavigationClient` | Sends goals to the follower and handles their asynchronous responses. |
| `tracking_` / `AstronautTracking` | Stores the latest astronaut pose and measures whether the person is stationary. |
| `route_handle_`, `astronaut_handle_` | Accepted mission requests; used to send feedback and final results to the requesting client. |
| `NavigationClient::handle_` | One follower action request. A mission can use many of these in sequence. |
| `rover` | Rover pose in the map frame, read from TF by `roverPose()`. |
| `target` | Person or marker pose used to calculate an approach goal. |
| `Pose` | Alias for `geometry_msgs::msg::PoseStamped`: timestamp, frame, position, and orientation. |

## Node setup — [src/nav_coordinator.cpp](../src/nav_coordinator.cpp)

Constructs the coordinator and keeps its basic bookkeeping.

| Function | Purpose |
| --- | --- |
| `NavCoordinator()` | Load settings, create TF and navigation components, initialize actions/subscriptions, and start the timer. |
| `canAccept()` | Check that navigation is free, the follower is available, and the goal is a valid pose in the configured map frame. |
| `begin()` | Reset mission data for a new job, save its waypoint, and clear tracking/command history. |
| `publishState()` | Publish the current state and diagnostic reason. |
| `phaseElapsed()` | Return seconds since the current phase began, using a steady clock. |

The component registration at the bottom lets ROS construct this node. The
executable is generated by CMake; there is no handwritten `main.cpp`.

## Incoming requests — `src/ros/`

### [mission_actions.cpp](../src/ros/mission_actions.cpp)

Owns the mission action servers and astronaut command handling.

| Function | Purpose |
| --- | --- |
| `initializeRouteAction()` | Register route goal validation, acceptance, and cancellation callbacks. An accepted goal calls `begin()` then `transitionOn(START)`. |
| `initializeAstronautAction()` | Register the equivalent callbacks for an astronaut mission. |
| `command()` | Validate command age/source, turn it into an event, and call `transitionOn()`. Wrong-phase commands are not queued. Remote STAY can also interrupt following recovery. |

### [mission_inputs.cpp](../src/ros/mission_inputs.cpp)

Receives observations and reads positions from TF.

| Function | Purpose |
| --- | --- |
| `initializeInputs()` | Subscribe to commands, astronaut poses, marker detections, map waypoints, and GPS waypoints. |
| `fresh()` | Check that a timestamp is valid, not in the future, and no older than the allowed age. |
| `mapPose()` | Validate a pose and transform it into the configured map frame; return no value if it cannot be used. |
| `roverPose()` | Read the latest map-to-rover TF and return a valid, recent rover pose, or no value. |
| `astronautFresh()` | Check that tracking contains a recent astronaut pose. |
| `markerFresh()` | Check that the mission contains a recent marker pose. |

The astronaut subscription checks age, calls `mapPose()`, and passes the pose to
`tracking_.observe()`. After a detection gap it resets stationarity history.
The marker subscription accepts only the requested ID during a route mission
and saves newer valid observations in `mission_.marker`.

A subscription's `[this](... message) { ... }` is a callback capturing the
current coordinator object. ROS runs its body when a message arrives, allowing
it to call that object's methods and update its members.

### [waypoint_requests.cpp](../src/ros/waypoint_requests.cpp)

Handles navigation without a multi-step mission.

| Function | Purpose |
| --- | --- |
| `waypoint()` | Validate a map waypoint, reject it during a mission, cancel any previous standalone drive, and select `NAVIGATING`. |
| `gpsWaypoint()` | Convert GPS to a map waypoint, then call `waypoint()`; report conversion failures. |

### [mission_parameters.cpp](../src/ros/mission_parameters.cpp)

`declareMissionParameters()` declares settings and rejects invalid values.
Normal overrides live in `config/mission.yaml`.

## Execution — [src/missions/mission_execution.cpp](../src/missions/mission_execution.cpp)

Connects events, state functions, and navigation outcomes.

| Function | Purpose |
| --- | --- |
| `updateMission()` | Timer callback: collect navigation results, handle stopping/recovery and timeouts, run the state function, and publish feedback. |
| `updateCurrentState()` | Select the state's function. Require recent rover TF for active navigation states; command-only waiting states need no operation. |
| `transitionOn()` | Ask the appropriate FSM for the next state. Ignore unmatched events. Use the stop barrier before STAYING or SUCCEEDED. |
| `changeState()` | Record the state and reset its deadline, operation-started flag, arrival flag, and reason. It sends no navigation goals. |
| `startNavigation()` | Save the goal and request it through `NavigationClient::replace()`. |
| `updateNavigationOutcome()` | Record follower success or start recovery on failure. State functions decide when to advance. |

`mission_.operation_started` prevents a state from starting its fixed operation
on every timer update. `mission_.navigation_reached` records successful follower
completion. Distance feedback alone does not set that flag.

## Route states — [src/missions/route_mission.cpp](../src/missions/route_mission.cpp)

| Function | State and purpose |
| --- | --- |
| `driveToWaypoint()` | NAVIGATING: start the waypoint drive once; on success, begin marker search or complete a standalone waypoint. |
| `searchForMarker()` | SEARCHING_ARUCO: wait for a matching recent detection, then advance after navigation stops. Search motion is a placeholder. |
| `calculateMarkerApproach()` | CALCULATING_APPROACH: calculate a goal short of the marker; recover if its observation is stale. |
| `driveToMarker()` | NAVIGATING_TO_ARUCO: start the approach once and wait for follower success. |
| `verifyMarkerArrival()` | VERIFY_ARRIVAL: compare rover and marker positions; succeed within the configured radius, otherwise retry the approach. |

## Astronaut states — [src/missions/astronaut_mission.cpp](../src/missions/astronaut_mission.cpp)

| Function | State and purpose |
| --- | --- |
| `driveToAstronaut()` | GO_TO_ASTRONAUT: drive to the initial waypoint once, then check successful navigation and waypoint distance. |
| `followAstronaut()` | FOLLOWING: update the trailing goal; when the person is stationary nearby, stop navigation and emit PERSON_STOPPED. |
| `waitForStay()` | WAIT_STAY: resume following if the person moves or leaves the arrival radius. Remote STAY arrives through `command()`. |
| `returnToAstronaut()` | COMING: track the person and advance only after follower success and a recent distance check. |
| `requireAstronautObservation()` | Shared check: start recovery if the tracked pose is missing or stale. |
| `updateAstronautNavigation()` | Shared follow/come work: calculate a standoff goal and limit how often it is replaced. |
| `completeToolPlaceholder()` | FETCHING/GIVING: emit simulated grasp/release confirmation after a delay if enabled; otherwise fail. |

WAIT_FOLLOW, STAYING, HOLDING_HAMMER, and WAIT_GIVE wait for valid commands.
`command()` emits their events; the timer still checks phase deadlines.

## Recovery and results — `src/missions/`

### [mission_recovery.cpp](../src/missions/mission_recovery.cpp)

| Function | Purpose |
| --- | --- |
| `retryStateOrFail()` | Spend one retry, remember the state to resume, and cancel navigation; fail if the retry budget is exhausted. |
| `updateRecovery()` | Wait for navigation to stop and required inputs to return, then restart the saved state; fail on recovery timeout. |
| `stopMission()` | Enter STOPPING, save the intended outcome, and cancel navigation. |
| `updateStopping()` | Wait until navigation is no longer busy, then enter STAYING or finish the mission. Keep ownership while waiting. |

### [mission_completion.cpp](../src/missions/mission_completion.cpp)

| Function | Purpose |
| --- | --- |
| `finishMission()` | Send the final action result, clear its handle, release ownership, and publish the terminal state. |
| `publishFeedback()` | Send current state and mission progress to the action client. |

## State rules — `src/fsm/`

| File / function | Purpose |
| --- | --- |
| `route_fsm.cpp` — `routeTransition()` | Map route state + event to next state. |
| `astronaut_fsm.cpp` — `astronautTransition()` | Map astronaut state + event to next state. |
| `mission_state.cpp` — `stateName()` | Convert the state enum to a readable string. |

These functions have no ROS calls. They assume the caller checked the completion
condition before emitting an event. An unmatched event preserves the state.

## Navigation components — `src/navigation/`

### [navigation_client.cpp](../src/navigation/navigation_client.cpp)

Owns one follower action at a time. Replacement cancels the old action before
sending the latest pending goal. Late callbacks from older goals are ignored.

| Function | Purpose |
| --- | --- |
| `NavigationClient()` | Create the ROS action client. |
| `ready()` | Check whether the follower action server is available. |
| `busy()` | Check whether a request is pending acceptance or has an active handle. |
| `distance()`, `replans()` | Read the latest follower feedback values. |
| `replace()` | Send a goal if idle; otherwise save the newest replacement and cancel the active goal. |
| `cancel()` | Clear any replacement and request cancellation. |
| `cancelAcceptedGoal()` | Send cancellation once a goal handle exists. |
| `takeResult()` | Return the stored outcome once, then clear it. |
| `send()` | Build a follower request and register response, feedback, and result callbacks. |
| `accepted()` | Handle goal acceptance/rejection, including cancellation requested before acceptance. |
| `completed()` | Translate the terminal ROS result into REACHED, FAILED, CANCELED, or STOPPED. |
| `finish()` | Clear the finished handle; send a pending replacement or store the outcome for the coordinator. |

### [astronaut_tracking.cpp](../src/navigation/astronaut_tracking.cpp)

Stores observations passed from `mission_inputs.cpp`; it has no subscription.

| Function | Purpose |
| --- | --- |
| `observe()` | Store a newer pose and reset the stationary anchor when the person moves far enough. |
| `reset()` | Clear the latest pose and stationary history. |
| `pose()` | Return the latest stored pose, if any. |
| `stationary()` | Check whether observations remained near the anchor for the required duration. |

### [mission_geometry.cpp](../src/navigation/mission_geometry.cpp)

| Function | Purpose |
| --- | --- |
| `validPose()` | Check finite position, a named frame, and a unit quaternion. |
| `distanceTo()` | Calculate planar distance between poses in the same frame, in meters. |
| `standoffGoal()` | Place a goal short of a person or marker along the rover-to-target line; stay put if already close enough. |

### [gps_waypoint_conversion.cpp](../src/navigation/gps_waypoint_conversion.cpp)

`convertGpsToMapWaypoint()` converts latitude/longitude to UTM, transforms that
point into map coordinates, and returns a pose with identity orientation.
It throws if the required transform is unavailable; `gpsWaypoint()` handles it.

Headers under `include/urc_state_machine/` declare the corresponding source
functions and component types. Three headers also describe shared data:

| File | Purpose |
| --- | --- |
| `nav_coordinator.hpp` | Declare the node's methods and owned ROS/components. |
| `active_mission.hpp` | Define mutable progress for the single active job. |

| `mission_parameters.hpp` | Define the validated settings held by the coordinator. |

| `mission_geometry.hpp`, `gps_waypoint_conversion.hpp` | Declare the geometry and GPS functions. |

| `CMakeLists.txt` | Compile the source files into one library, register the node executable, and install headers/config/docs. |
| `package.xml` | Declare ROS dependencies and package metadata. |
| `README.md` | Starting point: system flow, mission sequences, and running. |

| `docs/integration.md` | External publishers, interfaces, frames, and missing integrations. |
| `docs/code_guide.md` | This file/function reference. |

## Follow one request through the files

**Route goal:** `mission_actions.cpp` accepts it → `begin()` resets progress →
`transitionOn(START)` selects NAVIGATING → the timer calls `driveToWaypoint()` →
`startNavigation()` asks `NavigationClient` to send a follower goal → the result
is collected by `updateMission()` → `driveToWaypoint()` emits NAVIGATION_REACHED
→ `searchForMarker()` waits for the detection stored by `mission_inputs.cpp`.

**Astronaut pose:** topic callback in `mission_inputs.cpp` validates/transforms it
→ `AstronautTracking::observe()` stores it → `followAstronaut()` reads it →
`updateAstronautNavigation()` calculates and sends a trailing goal.

**Cancellation:** mission action cancel callback → `stopMission()` →
`NavigationClient::cancel()` → timer calls `updateStopping()` until the follower
stops → `finishMission()` returns CANCELED and releases ownership.
